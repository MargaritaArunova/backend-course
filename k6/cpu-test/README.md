# CPU Performance Testing

Скрипты для тестирования зависимости времени отклика от количества CPU при разных соотношениях операций вставка/чтение.

## Структура

```
k6/cpu-test/
├── load-test.js           # K6 скрипт нагрузочного тестирования
├── run-cpu-tests.sh       # Автоматический запуск тестов с разными CPU
├── analyze-results.py     # Анализ и визуализация результатов
├── README.md             # Документация
└── results/              # Директория с результатами (создается автоматически)
    ├── cpu_*.json        # JSON результаты k6
    ├── summary.csv       # Сводная таблица
    └── graphs/           # Графики
```

## Требования

### Системные зависимости
- Docker и Docker Compose
- k6 (https://k6.io/docs/get-started/installation/)
- Python 3.8+
- bash

### Python библиотеки
```bash
pip install matplotlib pandas
```

### Опциональные инструменты
- `jq` - для извлечения метрик из JSON (для bash скрипта)
- `bc` - для арифметических операций в bash

## Конфигурация

### Параметры docker-compose.yml

Убедитесь, что в `docker-compose.yml` настроены переменные окружения:

```yaml
app:
  environment:
    SPRING_DATASOURCE_URL: jdbc:postgresql://db:5432/socialdb
    SPRING_DATASOURCE_USERNAME: socialuser
    SPRING_DATASOURCE_PASSWORD: socialpass
    TOMCAT_MAX_THREADS: ${TOMCAT_MAX_THREADS:-200}
    SPRING_JPA_SHOW_SQL: ${SPRING_JPA_SHOW_SQL:-false}
  deploy:
    resources:
      limits:
        cpus: '${APP_CPU_LIMIT:-0.5}'
        memory: ${APP_MEMORY_LIMIT:-512M}
```

### Параметры тестирования

В файле `run-cpu-tests.sh`:

- `VUS=50` - количество виртуальных пользователей (постоянное)
- `DURATION="3m"` - длительность каждого теста
- `CPU_MIN=0.5` - минимальное количество CPU ядер
- `CPU_MAX=4.0` - максимальное количество CPU ядер
- `CPU_STEP=0.5` - шаг изменения CPU (половина ядра)
- `WRITE_RATIOS=("0.05" "0.50" "0.95")` - соотношения вставка/чтение (5/95, 50/50, 95/5)

## Запуск тестов

### 1. Подготовка окружения

```bash
cd k6/cpu-test

# Сделать скрипты исполняемыми
chmod +x run-cpu-tests.sh
chmod +x analyze-results.py
```

### 2. Запуск приложения

```bash
cd ../..
docker-compose up -d
```

### 3. Запуск тестирования

```bash
cd k6/cpu-test
./run-cpu-tests.sh
```

Скрипт автоматически:
1. Перебирает значения CPU от 0.5 до 4.0 с шагом 0.5
2. Для каждого значения CPU запускает тесты с 3 соотношениями вставка/чтение
3. Очищает базу данных между тестами
4. Сохраняет результаты в JSON файлы
5. Формирует сводную таблицу в CSV

### 4. Анализ результатов

```bash
./analyze-results.py
```

Скрипт создаст:
- Графики зависимости времени отклика от CPU
- Сравнение read vs write операций
- Статистику в CSV формате

## Результаты

### Графики

После выполнения `analyze-results.py` в `results/graphs/` будут созданы:

1. **cpu_vs_response_time_p95.png** - P95 время отклика vs CPU для разных соотношений
2. **cpu_vs_response_time_mean.png** - Среднее время отклика vs CPU
3. **cpu_vs_read_write_comparison.png** - Сравнение read и write операций для каждого соотношения

### CSV файлы

- **summary.csv** - сводная таблица с метриками
- **statistics.csv** - детальная статистика

## Параметры K6 теста

### Переменные окружения

- `BASE_URL` - URL приложения (по умолчанию: http://localhost:8080)
- `WRITE_RATIO` - доля операций записи (0.05, 0.5, 0.95)
- `VUS` - количество виртуальных пользователей (по умолчанию: 50)
- `DURATION` - длительность теста (по умолчанию: 5m)

### Ручной запуск одного теста

```bash
k6 run \
  -e BASE_URL="http://localhost:8080" \
  -e WRITE_RATIO="0.5" \
  -e VUS="50" \
  -e DURATION="3m" \
  load-test.js
```

## Метрики

### Собираемые метрики

- **read_response_time** - время отклика для операций чтения
- **write_response_time** - время отклика для операций записи
- **http_req_duration** - общее время отклика для всех запросов

### Статистики

Для каждой метрики собирается:
- Mean (среднее)
- P50 (медиана)
- P95 (95-й перцентиль)
- P99 (99-й перцентиль)
- Max (максимум)

## Соотношения операций

### 5/95 (WRITE_RATIO=0.05)
- 5% операций записи (создание пользователей, постов, комментариев)
- 95% операций чтения (получение списков пользователей и постов)

### 50/50 (WRITE_RATIO=0.50)
- 50% операций записи
- 50% операций чтения

### 95/5 (WRITE_RATIO=0.95)
- 95% операций записи
- 5% операций чтения

## Операции записи

Распределение операций записи:
- 40% - создание пользователей
- 40% - создание постов
- 20% - создание комментариев

## Операции чтения

Распределение операций чтения:
- 50% - получение всех пользователей (GET /users)
- 50% - получение всех постов (GET /posts)

## Troubleshooting

### Приложение не запускается

```bash
# Проверить статус контейнеров
docker-compose ps

# Проверить логи
docker-compose logs app

# Пересоздать контейнеры
docker-compose down
docker-compose up -d
```

### k6 не установлен

Установите k6: https://k6.io/docs/get-started/installation/

### Ошибка "command not found: bc"

```bash
# macOS
brew install bc

# Ubuntu/Debian
sudo apt-get install bc
```

### Ошибка при построении графиков

```bash
# Установить зависимости
pip install matplotlib pandas
```

## Примечания

- Тесты могут занять длительное время (3-4 часа для полного цикла)
- Рекомендуется запускать на машине с достаточным количеством CPU (минимум 4 ядра)
- База данных очищается между тестами для обеспечения чистоты эксперимента
- Перед каждым тестом создается предзаполнение (100 пользователей, 500 постов)
